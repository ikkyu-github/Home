# Singleton Inventory (PR-02)

Last updated: 2026-02-03

## Scope Rules

- **App-scope**: Allowed only for truly process-wide services that do not hold scene/tab-scoped mutable UI/runtime state (unless the service is explicitly the app-wide engine/router).
- **Scene-scope**: Must live on `SceneRuntimeContext` (or a scene-owned object) and be released on scene teardown.
- **Tab-scope**: Must live on `TabWebStore` and be released when a tab is invalidated/evicted.

## Legend

- **Effective scope**: what it behaves like today.
- **Correct scope**: where it should live under strict scene isolation.
- **Action**: keep / demote / remove / legacy.

## Notes / Follow-ups

- The remaining highest-risk violations are the **debug overlay singletons** storing `tabID` (`NavigationPolicyOverlayModel`, `PerformanceOverlayModel`). These should be moved onto `SceneRuntimeContext` so each scene has its own overlay state.
- `LifecycleCoordinator.shared` retains per-scene entries in a global map. This may be acceptable as an app-level router, but it should not own any per-scene WebKit/tab runtime objects that can leak across scenes.
